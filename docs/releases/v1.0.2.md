# Maven 1.0.2

## 中文

- **启动类识别与 Spring Boot 支持增强**
  - 识别组合式与自定义 `@interface` Boot 元注解：除 `@SpringBootApplication` 外，支持 `@SpringCloudApplication`、带有效 `main` 方法的 `@EnableAutoConfiguration` 类，以及反应堆多模块内基于它们组合定义的自定义 `@interface` 启动注解。
  - 支持 Java 21+/25 `void main()` 与紧凑源文件入口识别：无参 `void main()`、实例 `void main(String[])`、`static void main(String...)` 及无 `package`/`class` 头的紧凑源文件均可在“当前文件”及编译结果中识别并运行，同时拒绝 `private`/`abstract` 方法与 `@interface` 类定义。
- **运行准备与多模块启动修复**
  - 多模块应用默认工作目录改为工作区构建根目录（可在运行配置中显式覆盖），修复多模块项目相对路径与配置读取失败。
  - Spring Boot 与 WAR 模块运行时自动纳入 `provided` 作用域依赖（排除 `test`，可通过 `-Dlithe.runIncludeProvided=false` 关闭），解决内嵌容器或 `provided` 依赖缺失导致的 `ClassNotFoundException` / `NoClassDefFoundError`。
- **Maven 运行配置、构建树与设置体验完善**
  - 识别默认激活的 Maven Profiles（含 `<activeByDefault>` 与 `settings.xml` `<activeProfiles>`）并在构建树准确回显，支持通过 `-` 前缀取消激活，并在重开工程时保留状态。
  - 新增 `Maven` 任务运行配置类型（支持 `goals`、`-P`、`skipTests`、`-o`）及“Run Maven Goal”启动前任务，并补充设置搜索关键词。
  - 构建模型自动报告 Maven 实际使用的 `Settings File` 与 `Local Repository` 默认路径，在“构建选项”中可直观看见隐式默认值。
  - 编译与运行应用统一使用项目 JDK，移除单独的 `JDK (JAVA_HOME)` 构建选项（从 1.0.1 及更早版本升级后，旧的 `javaHome` 覆盖项不再生效，可在“构建选项”中清除）。

### 兼容性

需要 Lithe 桌面端 0.8.7 及以上（宿主需支持 `buildProviders: 1`、`runConfigurationTypes: 0` 与 `beforeLaunchTasks: 0`；推荐使用 0.8.10 及以上以配套桌面端构建探测、运行配置保存与模型失败提示修复）。更早的桌面端无法安装此版本，会继续使用原有兼容版本（1.0.1 或 1.0.0）；请先升级桌面端即可获得新版插件。读取项目工具可能执行项目代码及下载依赖。

## English

- **Expanded Startup Class & Spring Boot Detection**
  - Composed and cross-module custom `@interface` Boot meta-annotations: in addition to `@SpringBootApplication`, detects `@SpringCloudApplication`, `@EnableAutoConfiguration` classes with a valid `main` method, and custom `@interface` Boot annotations composed transitively across reactor modules.
  - Java 21+/25 `void main()` and compact source files: supports parameterless `void main()`, instance `void main(String[])`, `static void main(String...)`, and compact source files without a `package` or `class` header in both Current File discovery and compiled outputs, while rejecting `private`/`abstract` methods and `@interface` definitions.
- **Run Preparation & Multi-module Launch Fixes**
  - Multi-module application launches now default their working directory to the workspace build root (while honoring explicit overrides in the run configuration).
  - Spring Boot and WAR modules include `provided`-scope dependencies on the runtime classpath by default (excluding `test`, overridable with `-Dlithe.runIncludeProvided=false`), preventing missing container/API classes at runtime.
- **Maven Run Configurations, Build Tree & Settings**
  - Recognizes default-active Maven profiles (`<activeByDefault>` and `settings.xml` `<activeProfiles>`), preserves the active baseline in the Build tree, and supports deactivating profiles via the `-` prefix.
  - Declares a `Maven` task run configuration type (`goals`, `profiles`, `skipTests`, `offline`), a `Run Maven Goal` before-launch task, and settings search keywords.
  - Reports the effective default `Settings File` and `Local Repository` paths in the build model so Build Options shows implicit defaults when not overridden.
  - Unifies Maven builds and application launches on the Project JDK and removes the separate `JDK (JAVA_HOME)` build option (when upgrading from 1.0.1 or earlier, any previously saved `javaHome` option no longer takes effect and can be cleared in Build Options).

### Compatibility

Requires Lithe Desktop 0.8.7 or later (the host must support `buildProviders: 1`, `runConfigurationTypes: 0`, and `beforeLaunchTasks: 0`; 0.8.10 or later is recommended for paired build-probe, run-configuration-save, and model diagnostic fixes). Earlier desktop versions cannot install 1.0.2 and will keep their existing compatible version (1.0.1 or 1.0.0); upgrade the desktop app first to get this release. Reading project tools may execute project code and download dependencies.
